# iPhone・iPad・ドライバなしの Mac から印刷する

*[← README に戻る](../README.md)　/　English: [airprint.en.md](airprint.en.md)*

AirPrint（IPP Everywhere）のプリンタとして常駐させると、**iPhone / iPad / ほかの Mac** から
このプリンタに印刷できます。やり方は2つあり、どちらも v4.0 のパッケージに入っています。

| | 中身 | 向いている場面 |
|---|---|---|
| **PAPPL 版**（`mi700app`） | 自前のプリンタアプリケーション。給紙口や用紙名が日本語で出て、設定画面も付く | ふだん使う |
| `mi700ipp` | macOS 標準の `ippeveprinter` を常駐させるだけの軽い版 | 最小構成で試す |

仕組みの詳細と、調べて分かったことは [調べて分かったこと](findings.md) にまとめてあります。

## PAPPL で作ったプリンタアプリケーション

`ippeveprinter` で足りないところ（表示名のファイルを配れない・キューごとの設定を持てない）は、
**[PAPPL](https://www.msweet.org/pappl/)** で自前のプリンタアプリケーションを書くと埋まります。
[`driver/mi700pappl.c`](../driver/mi700pappl.c) がそれで、201PL の組み立ては
CUPS フィルタと共用しています（[`driver/mi700enc.c`](../driver/mi700enc.c)）。用紙は同じ `forms.conf` から読みます。

### 使い方

パッケージを入れると `mi700app` と本体（`/usr/local/libexec/mi700/mi700pappl`）が入ります。
あとは給紙口ごとにキューを作るだけです。

```bash
sudo mi700app add 192.168.1.160 "MultiImpact 700XX 単票" --source feeder
sudo mi700app add 192.168.1.160 "MultiImpact 700XX 連続紙" --source rear
sudo mi700app add 192.168.1.160 "MultiImpact 700XX 連続紙 ミシン目回避" --source front --perforation
mi700app list
sudo mi700app stop          # 止める(設定は残る。--purge で設定も消す)
```

- `sudo` 付きなら LaunchDaemon、なしなら LaunchAgent（`mi700ipp` と同じ）。既定のポートは 8632 です
- 設定画面は `http://localhost:8632/`。キューごとの既定値やセット済みの用紙を変えられます。
  同じ LAN の人も開けるので、気になる場合は `-o auth-service=other -o admin-group=admin` を
  付けて起動するとパスワードを要求します

### 自分でビルドする

```bash
# PAPPL を用意する（Homebrew には無いのでソースから）
curl -LO https://github.com/michaelrsweet/pappl/releases/download/v1.4.12/pappl-1.4.12.tar.gz
tar xzf pappl-1.4.12.tar.gz
(cd pappl-1.4.12 && ./configure --disable-shared --disable-libjpeg --disable-libpng && make)
driver/build-pappl.sh pappl-1.4.12

# 配布用(ユニバーサル)にするときは先にこちら。30〜60分かかるが1回で済む
driver/build-pappl-deps.sh      # OpenSSL と PAPPL を arm64 / x86_64 の両方でビルド
driver/build-pappl.sh           # build/deps を自動で見つけてユニバーサルにする
driver/build-pkg.sh 4.0         # パッケージに同梱(署名・公証も同じ手順)
```

**PAPPL は TLS に OpenSSL か GnuTLS を要求します**（macOS の Security.framework は使えません）。
Homebrew の OpenSSL は arm64 専用なので、そのままだと Apple Silicon 専用の実行ファイルになります。
`build-pappl-deps.sh` は OpenSSL を両アーキテクチャでビルドして `lipo` でまとめ、その上で PAPPL を
ユニバーサルでビルドします。OpenSSL は静的にリンクするので、できた実行ファイルが依存するのは
macOS 標準のライブラリだけです（`otool -L` で確認できます）。

### 取り戻せたもの

| | `ippeveprinter` 版 | PAPPL 版 |
|---|---|---|
| 表示名のファイル（`printer-strings-uri`） | 捨てられる | **配れる** |
| 用紙の種類 | OS の訳語だけ（便箋・写真） | **普通紙 (白黒)・写真 (グレースケール)** |
| 給紙口 | 標準キーワードに割り当て（主トレイ・手差し…） | **シートフィーダ (自動吸入)** など（Mac。iPhone は後述） |
| 用紙名 | 標準以外は寸法だけ（`10 x 11`） | **`forms.conf` の表示名** |
| ミシン目回避 | 用紙名が潰れて選べない | **キューの種類として選べる**（セット済み用紙の余白で効かせる） |
| キューの数 | 1プロセスに1台 | 1サーバに何台でも |

### iPhone に出せる文字列はここまで

iPhone の「プリンタオプション」で表示名のファイルを見てくれたのは**用紙の種類**だけでした。

| iPhone に出るもの | 表示 |
|---|---|
| 用紙の種類 | **表示名のファイルどおり**（独自の種類も日本語で出る） |
| 給紙口 | **`Com.mi700-feeder` のようにキーワードのまま** |
| 用紙サイズ | セット済みの用紙だけ（表示は OS 任せ） |
| **プリンタ名** | **そのまま**（日本語もそのまま出る） |

給紙口のキーワードから `com.` を外すと macOS がまるごと捨てるので、この形は変えられません。
そこで **給紙口ごとにキューを分け、名前を日本語にする**のが iPhone からはいちばん分かりやすい形でした。
プリンタを選んだ時点で給紙口と用紙が決まるので、オプションを触らずに済みます。
キューの種類は3つあります（`mi700app add` の `--source` と `--perforation` で選ぶ）。

| キューの種類 | 既定の給紙口 | セット済みの用紙 |
|---|---|---|
| `mi700`（単票） | シートフィーダ | A4 |
| `mi700-cont`（連続紙） | リアトラクタ | 連続紙 10x11インチ |
| `mi700-perf`（連続紙・ミシン目回避） | リアトラクタ | **連続紙 10x11インチ (ミシン目回避)**（上下 25.4mm） |

**ミシン目回避は「セット済みの用紙の余白」だけで効かせています。** クライアントはセット済み用紙の
余白の内側にしか描かないので、帯には何も来ません。本体にボトム領域（`ESC v66,06.` の `,06`）も
送りますが、**こちらは印字を止めません**（下の「実機の連続紙で確かめたこと」を参照）。

### PAPPL で分かったこと

- **自前の初期化（system callback）を使うなら `papplSystemAddListeners()` を自分で呼ぶこと。**
  呼ばないと UNIX ドメインソケットだけになり、ネットワークから見えません
- **フッタの HTML を渡さないと落ちます。** PAPPL 1.4.12 は `footer_html` が `NULL` のまま
  `papplClientGetLocString(client, NULL)` を呼び、`strcmp(NULL)` で落ちます。設定画面を開くたびに
  サーバが死に、`KeepAlive` がすぐ起こし直すので「ページが途中で切れる」ようにしか見えません
- **`black_1` を広告すると、クライアントが自分で 1bit にしてしまいます。** 白黒とグレーの
  切り替えをこちらで決めるには `sgray_8` だけを受け取ること
- **用紙ごとの余白は「セット済みの用紙」にしか乗りません。** PAPPL が持てるのはプリンタ全体の
  「上下」「左右」1組だけで、この機体のような非対称な余白（左1.6 / 右11.0 / 上8.7 / 下7.3mm）は
  表現できません。`media-col-database` を自分で足すこともできますが、PAPPL の生成分と**属性が重複**し、
  クライアントは先に出てくる PAPPL 側（余白 0）を読むので意味がありませんでした。
  iPhone はセット済みの用紙からしか選ばないので実害はありませんが、**Mac でセットしていない用紙を
  選ぶと余白 0 として描かれます**（右端が印字範囲から外れることがあります）
- 設定画面の「メディア」で用紙を変えると、**余白が 0 になります**（同じ理由）。用紙を替えるときは
  キューの種類を選び直すほうが確実です
- 独自の名前の用紙は、**寸法が PWG の標準サイズと一致すると標準名に読み替えられます**
  （`custom_cont10x11_254x279.4mm` → `na_10x11_10x11in`）。そのため同じ寸法の「(ミシン目回避)」用紙を
  **用紙名では見分けられません**。余白（`media-bottom-margin`）で判断しています
- `file://` のデバイスは、**存在する書き込み可能なディレクトリ**を指していないと拒否されます
- `format` を設定するなら `printfile_cb` も設定すること。片方だけだと `EINVAL` になり、
  「プリンタ名は英字で始めてください」という無関係なメッセージが出ます
- 状態は状態ファイル（root なら `/private/var/lib/mi700pappl.state`）に保存されます。
  古い設定が残って混乱したときは `mi700app stop --purge` で消せます

### 実機で確かめたこと（2026-10-13）

**iPhone から印刷できています。** Mac mini に v4.0-beta2 を入れて LaunchDaemon として常駐させ、
iPhone のプリント画面から「MultiImpact 700XX 単票」を選んで A4 を出しました。プリンタを選んだ時点で
給紙口（シートフィーダ）とセット済みの用紙（A4）が決まるので、オプションは何も触っていません。



フロントトラクタに **15x11インチの連続紙**をセットし、ミシン目回避のキューから3ページ印刷しました。

| 確認したこと | 結果 |
|---|---|
| 給紙口 | `ESC m1`（前トラクタ）✓ |
| 用紙長 | **`ESC v66.`**（66行 = 11インチ）✓ |
| 3ページの位置（出力データ） | 3ページとも **行159〜1600 で完全に一致**（ページごとのズレなし）✓ |
| 帯の中身の寸法（実測） | 上下の罫線間隔 **≈228mm**（設計 228.6mm）✓ |
| 帯の外の印字（実測） | **なし** ✓ |
| 用紙に対する位置（実測） | 全体に **2〜3mm 上寄り**（上 23mm / 下 28mm）。用紙のセット位置と、原点をリアトラクタで実測していることによる |

印刷前の確認は、デバイスを `file://` にしたキューを作って同じ経路を通すのが早いです。紙を使わずに
給紙口・用紙長・ページ位置まで確かめられます（`tools/mi700decode` で画像にも戻せます）。

このとき **キューの設定（ベンダーオプション）がジョブに届いていない**ことも分かりました。PAPPL は
ベンダーオプションをジョブの属性からしか拾わないので、クライアントが送ってこない設定は
プリンタ側の既定値を自分で見にいく必要があります。

### ボトム領域（`ESC v` の第2引数）は印字を止めません

**2026-10-13、実機で確かめました。** `ESC v66,06.`（ボトム領域 6行 = 25.4mm）を送った状態で、
わざと帯の中に線を置いたページを印刷しました。

| 仕掛けた線 | 結果 |
|---|---|
| 上の帯（ミシン目から 5・10・15・20mm） | **全部印字**（5mm の行は紙の上端で欠ける＝物理的な限界） |
| 下の帯（254mm より下の 258・262・266・270・274mm） | **全部印字**。次のミシン目まで 5.4mm のところまで出る |
| 勝手な改ページ | **なし**（2ページで紙2枚） |

ボトム領域は、おそらく**行送りで下端に達したときに自動で改ページするための設定**です。
このドライバはラスタを**絶対位置（`ESC T` と `ESC F`）で打つ**ので、その判定を一度も通りません。

**したがってミシン目回避は、用紙定義の余白（＝クライアントの版面）でしか実現できません。**
用紙の種類や独自オプションとして「ミシン目回避」を出しても、ボトム領域を送るだけでは何も起きません。
PPD 版の `MI700Bottom` も同じで、宣言はしますが印字は止まりません（ミシン目回避が要るときは
用紙サイズ「(ミシン目回避)」を選んでください）。規格どおりではあるので、送ること自体はやめていません。

### iOS から直接印刷するアプリは要りますか

この経路は「Mac を1台 AirPrint のプリンタに見せる」形ですが、**iPhone / iPad からプリンタの
9100 番へ直接 201PL を送る**こともできます。Mac もドライバも要りません。

考えているのは、**伝票を撮って背景に敷き、項目の位置を決めて保存し、入力して印刷する**
アプリです（`mi700align` でやっている位置合わせを画面でやる形）。ESC/P（エプソンの VP
シリーズ）にも対応すれば、国内のドットインパクトはほぼ覆えます。複写伝票は今も
ドットインパクトでしか刷れないので、現場で書いて即複写という業務には合うはずです。

**「あったら使う」という方は
[Issue #1](https://github.com/yukino1230/multiimpact-700xx-macos-driver/issues/1) で教えてください（👍 だけでも助かります）。**
使う機種（メーカー・型番）と、刷りたい伝票の種類も書いてもらえると助かります。需要が見えたら作ります。

## 動かし方

**`mi700ipp`** で常駐させます。macOS 標準の `/usr/bin/ippeveprinter` を launchd に登録し、
「MultiImpact 700XX」として Bonjour に名乗らせます。

```bash
sudo mi700ipp add 192.168.1.160            # 常駐させる(ログインしていなくても動く)
mi700ipp list                               # 一覧
sudo mi700ipp remove                        # 外す
```

| | sudo 付き | sudo なし |
|---|---|---|
| 登録先 | LaunchDaemon | LaunchAgent |
| 動く時間 | **常に**（印刷サーバ向け） | そのユーザーがログインしている間 |
| ログ | `/Library/Logs/mi700/<ポート>.log` | `~/Library/Logs/mi700/<ポート>.log` |

名前とポートは `mi700ipp add <IP> "名前" --port 8632` で変えられます。

登録すると、同じネットワークの **Mac（システム設定から追加）と iPhone** から印刷できます。
**このドライバを入れた Mac から追加すると PPD が自動で選ばれ**、ミシン目回避なども含めた
今までどおりの UI で、同じサーバに印刷できます（変換済みのデータをそのまま通します）。

中身は次の3つです。

- [`driver/mkippattr.py`](../driver/mkippattr.py) — `forms.conf` から属性ファイルを作る（`mkppd.py` の IPP 版）
- [`contrib/mi700ippcmd`](../contrib/mi700ippcmd) — ジョブごとに呼ばれ、URF / PWG Raster を `rastertomi700` に渡す。
  ドライバで変換済みの 201PL（先頭が `CAN ESC M`）はそのまま通し、それ以外は断る
- `ippeveprinter` の起動引数:

```bash
ippeveprinter -D socket://<IP>:9100 -c /usr/local/libexec/mi700/mi700ippcmd \
              -a mi700.conf -r _print,_universal "MultiImpact 700XX"
```

**`ippeveprinter` のオプションには、組み合わせられないものがあります。** どれも Usage を出して止まるだけで、
理由は表示されません。

| 組み合わせ | 代わりに |
|---|---|
| `-P`（PPD）と `-c`（変換コマンド） | 属性は `-a` のファイルに書く |
| `-a` と `-f`（受け付ける形式） | `document-format-supported` を属性ファイルに書く |
| `-a` と `-M` / `-m`（メーカー・機種名） | `printer-make-and-model` を属性ファイルに書く |

ほかに、実際に動かしてみて分かったことです。

- **`media-size-supported` を書かないと、用紙を指定したジョブが拒否されます**
  （`Unsupported media-col collection value`。既定の letter / legal / a4 と照合されるため）
- **給紙口は `IPP_MEDIA_SOURCE` ではなく `IPP_MEDIA_COL` の中で届きます**（`{media-source=rear ...}`）
- `-a` を使っても、`ippeveprinter` は自前の `document-format-supported` を**追加します**。
  属性が重複しますが、先に出たほう（属性ファイル側）が使われます
- **stderr の `STATE:` / `INFO:` / `ERROR:` / `DEBUG:` は CUPS フィルタと同じ作法**なので、
  用紙切れの通知もそのまま動きます。ただし **CUPS と違ってジョブが終わっても状態が片付きません**。
  開始時の「用紙なし」を持ち続けると iPhone が「用紙がセットされていない」として次のジョブを
  送らなくなるので、フィルタはジョブの終わりにもう一度状態を調べ直します
- ドライバを入れた Mac（PPD）からは `Create-Job` + `Send-Document` で届きます。
  `Print-Job` で `application/octet-stream` を送ると、`ippeveprinter` が中身から形式を推定しようとして
  入口で断りますが、実際のクライアントはこの経路を使いません

## iPhone から印刷したい場合

**iPhone から印刷できます**（メモから A4 で確認）。Mac のシステム設定から追加した場合と同じく URF で届き、
給紙トレイ・メディアタイプ・プリント品質・排紙トレイが選べます。

- **用紙サイズは `media-ready`（セット済みの用紙）からしか選べません。** 属性ファイルで A4 だけを
  セット済みにしていたら、iPhone では A4 しか出てきませんでした。全用紙を載せています
- 黒い文字は値 69 のグレーで届きます（上の「白黒 / グレースケール」を参照）
