# 調べて分かったこと

*[← README に戻る](../README.md)　/　English: [findings.en.md](findings.en.md)*

このドライバを作る過程で、実機とマニュアルで確かめたことの記録です。
**使うだけなら読まなくて構いません。** 同じことをやろうとしている人と、将来の自分のために残してあります。

## 他に選択肢はあるか

探した範囲では、**macOS のプリンタとして完結する実装は見当たりませんでした。**
いちばん近いのは Ghostscript の `pr201` 出力デバイスで、OpenPrinting にも登録があります。

手元の Ghostscript 10.07 で動かして中身を確認しました。`ESC F`（横位置）と
`ESC J`（24ドットビットイメージ）で組み立てる、**このドライバとまったく同じ構造**の出力でした。
`ESC T18` = 18/120インチ = 160dpi での24ドットちょうど、という点も一致します。
別々に作られた実装が同じ結論に達しているので、**こちらの解析の裏づけにもなっています。**

ただし `pr201` デバイスが出すのはビットイメージだけで、次のものはありません。

- 給紙口の選択、カット紙の排出方向、用紙長、印刷品質
- **印字可能範囲の制御**（超えるとプリンタがエラーで停止します）
- macOS の印刷ダイアログとの統合（PPD もキューもないので、CUPS への組み込みは自前）
- Ghostscript への依存が残る

つまり「PDF を PR201 のドットに変換する」ところまでは既にあって、
**macOS のプリンタとして成立させる部分が無かった**、というのが実情のようです。
このドライバはそこを埋めるものです。

## macOS で連続紙は扱えないのか

「macOS の印刷の仕組みでは連続紙のプリンタは使えない」という説明を見かけます。
正確には**使えないのではなく、連続紙という概念が存在しない**だけです。

macOS の印刷は Quartz → PDF → CUPS ラスタという流れで、アプリが作るのは
**寸法の確定した独立したページの集まり**です。「終わりのない紙が流れ続ける」という
モデルがどこにもないので、次のものは表現する手段がありません。

| 連続紙で必要なもの | macOS 側の受け皿 |
|---|---|
| 用紙先頭（top of form） | なし。プリンタ側の状態で、印刷系からは触れない |
| ミシン目送り・引き戻し | なし。IPP にも PPD にも該当する属性がない |
| ページ境界をまたぐ連続印字 | できない。ページは独立している |
| **給紙口ごと**の印字可能領域 | なし。PPD の `ImageableArea` は**用紙サイズ単位** |

### このドライバでの扱い方

**連続紙の1フォームを、その長さのページとして定義します。** `Cont10x11` は
254 × 279.4mm（10×11インチ）です。CUPS から見ればただの1ページで、フィルタが
ページ末尾に FF を出すと、プリンタが自分の用紙長に従って次のミシン目まで送ります。
用紙長はジョブごとに `ESC v` で上書きするので、本体設定とのズレも起きません。

**ミシン目送りと引き戻しはプリンタ本体の機能に任せます。** macOS 側に表現がないので、
実装しない判断をしました。本体が持っている機能なので、これで困りません。

上の表の最後の項目は実際に問題になりました。ミシン目まわり 25.4mm を空けるかどうかは、
Windows のドライバでは「リアトラクタ」と「リアトラクタ(上下余白0)」という**給紙口の2択**です。
PPD では給紙口ごとに印字領域を変えられないので、**用紙サイズを2種類用意して名前で見分ける**
形にしました（`連続紙 10x11インチ` と `連続紙 10x11インチ (ミシン目回避)`）。

### 長さ自体は制約になりません

「連続紙＝長いものが刷れない」と思われがちですが、この PPD は任意長のページを許可しています。

```
*MaxMediaHeight: "10000"     (= 10000pt ≒ 3.5m)
```

**1ページを 3.5m まで定義できる**ので、ミシン目をまたぐ長い表も「そういう寸法のページ」として
作れば刷れます。ページという枠に収まりさえすれば、長さは問題になりません。

### 本当に厄介なのは印字可能範囲

macOS は `ImageableArea` を信じてその範囲でラスタを作ります。**ここを間違えると
用紙外に印字しようとしてプリンタが物理的に停止します。** 最近のプリンタなら黙って
切り捨てるところを、この世代の機械はアラームで止まります。移植時にいちばん時間を
取られるのはここだと思います。

## PPD が使えなくなったときの移行先

Apple は PPD ベースの従来型ドライバを非推奨としています。そうなった場合の移行先は
**IPP Everywhere のプリンタアプリケーション**です。実際に試したうえでの記録を残しておきます。

## 変換部分はそのまま使えます

IPP Everywhere / AirPrint でプリンタが受け取るのは **PWG Raster か URF（Apple Raster）** です。

- **PWG Raster** は CUPS Raster v2 をベースにした規格で、**マジックもヘッダ構造も同じ**（`RaS2`）。
  このフィルタは libcups に依存せずラスタを自前で解析しているので、手を加えずに読めます
- **URF** は構造の近い別形式です。**読み込みを足してあります**（8bit グレーを 8×8 の組織的ディザで 1bit に）

URF はグレーで届くので、網掛けの濃さはこちらで決めることになります。ドットインパクトは点が
広がって隣とつながるため、そのままディザにすると**点を半分打った時点でほぼ塗りつぶし**に見えます
（実測で 50〜90% が 49〜56% に詰まった）。実測値から打つ割合を逆算する補正を入れ、
**10% ごとにほぼ均等な濃さ**（7・13・19・24・32・38・42・50・55%）になりました。

網掛けにするかどうか（白黒かグレースケールか）は、印刷ダイアログの**用紙の種類**で選びます。

| iPhone | Mac | 処理 |
|---|---|---|
| 自動選択（初期状態） | （指定なし） | **白黒**: 半分より暗ければ打つだけ（補正もディザもしない） |
| 普通紙 | 便箋 | 白黒 |
| **写真** | **写真用紙** | **グレースケール**: 上の補正をかけて組織的ディザ |

「便箋」「普通紙」「写真」は OS の訳語です（IPP の `stationery` / `photographic`）。
ドライバが中身を見て白黒かグレーかを推測することはしていません。

白黒/グレースケールのための標準の項目（`print-color-mode`）は使えませんでした。

- **Mac も iPhone も、モノクロのプリンタには切り替えを出さず、常に `monochrome` を送ってきます**
- カラー対応と偽ると iPhone に「カラーでプリント」が出ますが、**初期状態（オン）では何も送ってこない**ので、
  既定値をどちらにしても、スイッチの表示と逆になるか、何も触らないと網点になるかのどちらかでした
- 内容の最適化（`print-content-optimize`: テキスト / 写真）はいちばん意味が合いますが、Mac にも iPhone にも出ません

なお iPhone は黒い文字を真っ黒（0）ではなく **値 69 の一色**（約 73% のグレー）で送ってくるので、
グレースケールのプリンタで刷ると文字が網点になります

どちらも**ページ全体がラスタ**になっている点が CUPS ラスタと違います。CUPS ラスタは
印字可能範囲ぶんしか無いので余白ぶんずらし戻していますが、ページ全体のラスタで同じことをすると
二重にずれます（A4 で下に 8.4mm）。フィルタはラスタの高さとページの高さを比べて判断しています。

## Mac からの追加方法で、届く形式が変わります

| 追加方法 | 条件 | 届く形式 |
|---|---|---|
| `lpadmin -m everywhere` | PWG Raster だけでも可 | PWG Raster |
| **システム設定**（プリンタとスキャナ） | **URF の広告と `-r _print,_universal` の両方が必要** | **URF** |

PWG Raster だけを広告した場合は、システム設定のドライバ欄に AirPrint の選択肢が出てきません。
**ふつうの人がふつうに追加できるようにするには URF が必須**でした。

また、**このドライバが入っている Mac では、機種名が一致すると PPD のほうが自動で選ばれます**。
その場合は今までどおりの UI になり、手元で 201PL に変換したデータが届きます。
`mi700ippcmd` はそれをそのままプリンタへ通します。

## 失われるもの

システム設定から追加したときの印刷ダイアログは、次のようになりました。

| | PPD（今の方式） | IPP Everywhere |
|---|---|---|
| 用紙名 | `A4`・`連続紙 10x11インチ` | 標準の用紙は訳される（`A4`・`JIS B4`・`レター`）。**それ以外は `10 x 11`・`55x91mm` のように寸法だけ** |
| **ミシン目回避** | 使える | **消える**（同じ寸法の通常版に潰れる） |
| 給紙口 | シートフィーダ・シートガイド・リアトラクタ・フロントトラクタ | **主トレイ・手差し・リアトレイ・下段トレイ**（macOS の訳語） |
| 排出方向 | 手前側・奥側 | 「仕上げオプション」の中に **Front・背面** |
| **印刷品質** | 4種類 + 指定なし | **下書き・標準・最高の3段階**（片方向のドラフトが選べない） |
| 白黒 / グレースケール | （アプリ側で決まる） | **用紙の種類で選ぶ**（写真＝グレー、それ以外＝白黒） |
| **ボトム領域** | 使える | **消える**（対応する標準属性が無い） |

給紙口に独自の名前（`reartractor` など）を付けても、**macOS は IPP 標準のキーワード以外を捨てます**。
そのため `main` / `manual` / `rear` / `bottom` に割り当て、`mi700ippcmd` で読み替えています。

### ミシン目回避を取り戻せないか試したこと

複合機（ブラザーなど）は、独自の用紙の種類（`com.brother-hagaki-…`）に日本語名を付けて
AirPrint でも見せています。同じ方法を試しました。

| 方法 | 結果 |
|---|---|
| 独自の用紙の種類（`com.mi700-perforation`） | **iPhone には出ない**。Mac ではキーワードのまま出る |
| 表示名のファイル（`printer-strings-uri`） | **`ippeveprinter` が属性を捨てる**。複合機はプリンタ本体がこのファイルを配っている |
| 標準の種類「連続用紙」（`continuous`）に上下 25.4mm の余白を持たせる | 一覧には出るが、**iPhone は種類ごとの余白を使わない**（用紙サイズの余白で描く） |

標準の種類は iPhone にも Mac にも日本語名で出ます（連続用紙・フォーム - マルチパート・ラベル・
封筒など）。ただし使い道は、「写真ならグレースケール」のように**種類によってこちらの処理を変える**ことに
限られます。ミシン目回避が要る連続紙は、ドライバ（PPD）を入れた Mac から印刷してください。
同じ `mi700ipp` のサーバ経由でも、PPD が選ばれていれば今までどおり使えます。

**この2つは、表示名のファイルを自分で配れば解決します。** `ippeveprinter` では配れませんが、
PAPPL で自前のプリンタアプリケーションを書くと配れます（下の
「[PAPPL で作ったプリンタアプリケーション](airprint.md#pappl-で作ったプリンタアプリケーション)」）。

### 「アプリを入れれば AirPrint のまま独自の設定が出せる」という説明について

AI やネットの記事で、次のような説明を見かけることがあります。**2026年9月、macOS 27 で確かめた限りでは、どれもこのプリンタには当てはまりません。**

| よく見かける説明 | 実際 |
|---|---|
| 「プリント拡張機能アプリ」（`UIPrintServiceExtension`）で、印刷ダイアログに独自の設定画面を差し込める | **iOS / iPadOS（と Mac Catalyst）の、プリンタを探すための拡張機能**。メソッドは `printerDestinations(for:)` の1つだけで、画面を差し込む機能は無い |
| `NSPrintPanelAccessorizing` で印刷ダイアログに独自の設定欄を足せる | 実在するが、**自分のアプリの**印刷ダイアログ用。Finder・ブラウザ・Pages など他のアプリには効かない |
| 独自の設定値は CUPS がベンダー独自の IPP 属性に変換してプリンタへ送る | **送られない**。ドライバなしのキューに `-o mi700-bottom=6`・`-o com.mi700-bottom=6`・`-o MI700Bottom=6` を付けて印刷したところ、3つとも CUPS の段階で捨てられ、`ippeveprinter` には届かなかった |
| メーカーはシステム拡張やヘルパーアプリで印刷ダイアログを拡張する方式に移行している | 裏付けが見つからない。業務用の複合機も macOS 26・27 向けに **PPD を配っている** |

「AirPrint のまま、アプリでメーカー独自の設定画面を出す」のは **Windows の Print Support App** の仕組みです。
macOS には、今のところ同じものはありません（昔の Print Dialog Extension は PPD に結び付いたプラグインで、
AirPrint では使えません）。

AirPrint のまま独自の機能を扱う方法は、次の2つだけでした。

- **IPP の標準の属性に割り当てる**（給紙口・品質・用紙の種類。このリポジトリでやっていること）
- **ドライバ（PPD）の経路を使う**（`mi700ipp` のサーバ経由でも使える）

**今すぐ移行する理由はありません。** PPD 経路のほうが UI は優れており、macOS 27 の時点で
問題なく動いています。これは「そのときが来たら何をすればよいか」の記録で、
実装は `ipp-everywhere` ブランチにあります。

属性ファイルの生成・URF の読み込み・実機での検証結果は
[`ipp-everywhere` ブランチ](https://github.com/yukino1230/multiimpact-700xx-macos-driver/tree/ipp-everywhere)
で進めています。

## 実機で検証したこと

Windows ドライバが出力したデータを `FILE:` ポートで吸い出し、それと突き合わせて確定させました。
**推測ではなく、出力を測って確認したもの**です。

さらに 201PL リファレンスと 700XX2/JX3 のユーザーズマニュアルを、**実装が出す制御コード1つずつと突き合わせて精査しました**（2026-09-16）。齟齬はありませんでした。
実測で突き止めた「LSB が上端」「`ESC T` は 1/120 インチ」も、そのまま文書に記載がありました。

- **解像度は縦横とも 160dpi**（正方ピクセル）。全角24×24ドットの正方性から逆算
- `ESC J nnnn` + データ = 24ドットビットイメージ。1列3バイト、**バイト内は LSB が上端**
- `ESC F nnnn` = 横方向の絶対位置。1ドット = 1/160 インチ
- `ESC T nn` + LF = 縦方向の紙送り。**単位は 1/120 インチ**（1/180 ではない）、0〜99
- `ESC m 1/2/3` = 給紙口。**シートフィーダは `ESC a`（全排出後全吸入）が要る。**
  これを送らないと給紙後に「印刷可」を押すまで印刷が始まりません。
  シートガイドとの違いはこのコードを送るかどうかだけです
- **座標系は Windows ドライバと完全に一致します。** 実際に伝票へ正しく印字できた
  キャプチャを画像に戻し、このドライバに通し直すと、インク5176ドットが1つ残らず同座標に来ます
- **用紙外に印字しようとするとプリンタが停止します。** 本体表示は
  アラーム・高速印刷・用紙PE の点滅。A4 なら x=0 が用紙左端から 4.7mm 内側なので
  右限界は 205.3mm = 1293ドット。対処は PPD の `ImageableArea` を正しく書くことです
- **双方向印字のバンド境界のズレは本体の「罫線ぞろえ」で直ります。**
  1200dpi でスキャンして実測したところ、調整前 0.13mm が
  標準印字 0.011mm / ドラフト 0.060mm になりました（ドットピッチは 0.159mm）。
  ドット列印刷は**標準印字が HD、ドラフトが NHS** の調整に従います（マニュアルには記載なし）
- **ラスタは印字可能範囲ぶんしか無い。** CUPS ラスタの (0,0) はページ原点ではなく
  `ImageableArea` の左上です。ヘッダの `Margins` と `ImagingBoundingBox` を読んで
  その分ずらし戻さないと、**内容が左上にずれて印刷されます**（連続紙は余白0なので影響なし。
  カット紙で実測して発覚しました）。CUPS が持っているのは整数ポイントなので 0.2mm ほど丸められます
- **`FS 05v`（カット紙の用紙長）はどちらのマニュアルにも載っていません。** Windows の
  キャプチャ2つから逆算しました。単位は 1/120 インチで、**カット紙のときだけ +300（2.5インチ）**
  が付きます（連続紙の捕獲は `540` = 4.5インチちょうど、A4 のカット紙は `1703` = 11.69インチ + 2.5インチ）。
  これは**用紙の長さ**であってラスタの高さではありません。連続紙の `ESC v`（行数）も同じで、
  ミシン目回避の用紙（上下25.4mm）でラスタの高さを使うと2インチ短くなり、
  **改ページのたびに2インチずつずれていきます**（3.4 で修正）
- **SNMP は Host Resources だけ。** `hrPrinterDetectedErrorState` で用紙切れ・カバー開・
  紙詰まり・オフラインが取れます。Printer-MIB (1.3.6.1.2.1.43) は未実装なので、
  用紙残量・リボン残量・装着オプションは取得できません

## 推定にとどまること

- **A3 / B4 の対応**は 700XX2 の資料の表から読み取ったもので、700XX の実機では試していません
- **印字可能範囲**は NEC「用紙設計説明書」の**推奨印刷範囲**からの計算です。
  最大印刷範囲は「用紙ジャム、印刷ヘッドの故障等が発生する場合があります」と
  明記されているため採用していません
- **封筒・名刺**のサイズは定型用紙表からの引き写しで、給紙の可否は未確認です
- **原点オフセット**（カット紙 左4.7mm/上1.0mm、トラクタ 左32mm/上0mm）は実測値ですが、
  **トラクタの物理位置で変わります**。用紙を入れ替えたら `mi700align` で測り直してください
- 他の 201PL 系プリンタで動くかどうか

## 設計上の判断

- **ソフトウェアでの位置補正は入れていません。** 連続紙の位置合わせはトラクタを
  物理的に動かすのが本来の方法で、ソフトで補正すると責任が2箇所に分散し、
  設定が古くなっても**エラーにならず静かにズレます**
- **ページサイズは用紙の実寸**で定義しています。Windows のフォーム定義と同じにすることで、
  座標が完全に一致する利点を優先しました
- **ミシン目回避（上下25.4mm）は用紙サイズとして持たせています。** 本来は給紙口の属性ですが、
  PPD の `ImageableArea` は用紙サイズ単位でしか指定できないためです
