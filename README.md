# MultiImpact 700XX を macOS から使う

NEC のドットインパクトプリンタ **MultiImpact 700XX** 用の CUPS ドライバです。
NEC は本機の macOS 用ドライバを提供していないため、201PL（PC-PR201 系）の制御コードを
直接組み立てる CUPS フィルタを書きました。アプリの印刷ダイアログからそのまま印刷できます。

> A CUPS driver for the NEC MultiImpact 700XX dot-matrix printer on macOS.
> NEC ships no macOS driver for this printer; this one speaks 201PL (PC-PR201) directly.

**現在の版は [v3.4](https://github.com/yukino1230/multiimpact-700xx-macos-driver/releases/tag/v3.4)**（署名・公証済みの pkg を [Releases](https://github.com/yukino1230/multiimpact-700xx-macos-driver/releases) で配布しています）。
**iPhone / iPad からも印刷できる試験版 [v4.0-beta1](https://github.com/yukino1230/multiimpact-700xx-macos-driver/releases/tag/v4.0-beta1)** もあります。
PPD を使わずに AirPrint のプリンタとして常駐させる版で、[`ipp-everywhere` ブランチ](https://github.com/yukino1230/multiimpact-700xx-macos-driver/tree/ipp-everywhere)で開発しています。

> Current release: **v3.4**. A beta, **v4.0-beta1**, adds printing from iPhone/iPad and driverless Macs
> by running the printer as an AirPrint (IPP Everywhere) service without a PPD (`ipp-everywhere` branch).

**ドットインパクトプリンタ**は複写伝票や連続紙の印刷に今も使われていますが、
メーカーは macOS 用のドライバを出していません。「Mac から印刷できない」
「Windows でしか使えない」と諦めていた方に向けたものです。
対象は **PC-PR201 / PR201 / 201PL** 系のプリンタ言語を話す機種です。

## 特徴

- **印刷ダイアログから普通に印刷できる。** 給紙口・用紙サイズ・印刷品質を選べます
- **外部依存なし。** PDF のラスタライズは macOS 標準の `cgpdftoraster` に任せ、
  CUPS ラスタ → 201PL の変換だけを C で行います。Ghostscript も libcups も要りません
- **用紙定義はテキストファイル1つ。** `forms.conf` に1行足せば用紙が増えます
- **プリンタの状態を印刷キューに出します。** 用紙切れやカバー開のときに理由が表示されます
- **iPhone からも印刷できます（試験版 v4.0-beta1）。** AirPrint のプリンタとして常駐させます。
  詳しくは「[PPD が使えなくなったときの移行先](#ppd-が使えなくなったときの移行先)」

## 対象機種

| | |
|---|---|
| 実機で検証済み | **MultiImpact 700XX**（LAN ボード内蔵、RAW 9100） |
| 文書上は動くはず | **MultiImpact 700XX2 / 700XX2N / 700JX3 / 700JX3N**（**実機未検証**） |
| たぶん動く | その他の 201PL 系（**未検証**） |

700XX2 と 700JX3 については、マニュアルで裏を取ってあります。

- **1冊のマニュアルが XX2 と JX3 の両方をカバーし**、「700XX2」を「700JX3」と読み替えるだけ、
  と明記されています。制御コード表も両者を区別していません
- **このドライバが使うコマンドは、拡張制御コード表で全て「○（有）」**です
  （`ESC J` `ESC F` `ESC T` `ESC M` `ESC H` `ESC m` `ESC a` `ESC b` `ESC >` `ESC ]`
  `ESC d` `ESC v` `ESC L` `ESC /` `ESC e` `ESC f` `ESC c8` `FS 05F` `FS 02ER/EF` `EM`）
- **解像度は「MultiImpact700 の解像度は 160dpi のみ」**と明記されています。
  移植でいちばん怖い解像度の違いが、700 シリーズ内では起きません

ただし**実機で試していません**。同じ表で `ESC n0` / `ESC n1`（NHS/SHS パイカ）が
XX2/JX3 では「×（無）」になっているとおり、**700XX と XX2/JX3 でもコマンドに差はあります**。
このドライバはそれらを使っていませんが、「動くはず」以上のことは言えません。

印字可能範囲は機種ごとに違うので、いずれにせよ `forms.conf` の調整が必要です。

## 動作環境

| | |
|---|---|
| 検証済み | **macOS 27.0** および **26.6.2**（いずれも Apple Silicon、実機で印刷まで確認） |
| たぶん動く | macOS 11 以降（**未検証**） |

26 から 27 へのアップグレードでは、**ドライバ・キュー・PPD がそのまま残り、印刷も問題ありません**
（未署名のフィルタもそのまま動きました）。ただし **CUPS の Web 設定画面が無効化されています**。
キューの既定値は `mi700default` を使ってください（[詳しくは下記](#ブラウザから設定するmacos-26-まで)）。

フィルタは arm64 と x86_64 のユニバーサルバイナリとしてビルドされます。
ビルドには **Xcode Command Line Tools**（`clang`）と **python3** が要ります。

```bash
xcode-select --install
```

> **注意:** Apple は PPD ベースの従来型プリンタドライバを非推奨としており、
> 将来の macOS で動かなくなる可能性があります。このプリンタは AirPrint に対応できないため、
> そうなった場合は CUPS を別途用意するなどの回避が必要になります。
> **macOS 27.0 の時点では問題なく動いています**（実機で印刷まで確認）。

## 他に選択肢はあるか

探した範囲では、**macOS のプリンタとして完結する実装は見当たりませんでした。**
いちばん近いのは Ghostscript の `pr201` 出力デバイスで、OpenPrinting にも登録があります。

手元の Ghostscript 10.07 で動かして中身を確認しました。`ESC F`（横位置）と
`ESC J`（24ドットビットイメージ）で組み立てる、**このドライバとまったく同じ構造**の出力でした。
`ESC T18` = 18/120インチ = 160dpi での24ドットちょうど、という点も一致します。
別々に作られた実装が同じ結論に達しているので、**こちらの解析の裏づけにもなっています。**

ただし `pr201` デバイスが出すのはビットイメージだけで、次のものはありません。

- 給紙口の選択、カット紙の排出方向、用紙長、印刷品質
- **印字可能範囲の制御**（超えるとプリンタがエラーで停止します）
- macOS の印刷ダイアログとの統合（PPD もキューもないので、CUPS への組み込みは自前）
- Ghostscript への依存が残る

つまり「PDF を PR201 のドットに変換する」ところまでは既にあって、
**macOS のプリンタとして成立させる部分が無かった**、というのが実情のようです。
このドライバはそこを埋めるものです。

## macOS で連続紙は扱えないのか

「macOS の印刷の仕組みでは連続紙のプリンタは使えない」という説明を見かけます。
正確には**使えないのではなく、連続紙という概念が存在しない**だけです。

macOS の印刷は Quartz → PDF → CUPS ラスタという流れで、アプリが作るのは
**寸法の確定した独立したページの集まり**です。「終わりのない紙が流れ続ける」という
モデルがどこにもないので、次のものは表現する手段がありません。

| 連続紙で必要なもの | macOS 側の受け皿 |
|---|---|
| 用紙先頭（top of form） | なし。プリンタ側の状態で、印刷系からは触れない |
| ミシン目送り・引き戻し | なし。IPP にも PPD にも該当する属性がない |
| ページ境界をまたぐ連続印字 | できない。ページは独立している |
| **給紙口ごと**の印字可能領域 | なし。PPD の `ImageableArea` は**用紙サイズ単位** |

### このドライバでの扱い方

**連続紙の1フォームを、その長さのページとして定義します。** `Cont10x11` は
254 × 279.4mm（10×11インチ）です。CUPS から見ればただの1ページで、フィルタが
ページ末尾に FF を出すと、プリンタが自分の用紙長に従って次のミシン目まで送ります。
用紙長はジョブごとに `ESC v` で上書きするので、本体設定とのズレも起きません。

**ミシン目送りと引き戻しはプリンタ本体の機能に任せます。** macOS 側に表現がないので、
実装しない判断をしました。本体が持っている機能なので、これで困りません。

上の表の最後の項目は実際に問題になりました。ミシン目まわり 25.4mm を空けるかどうかは、
Windows のドライバでは「リアトラクタ」と「リアトラクタ(上下余白0)」という**給紙口の2択**です。
PPD では給紙口ごとに印字領域を変えられないので、**用紙サイズを2種類用意して名前で見分ける**
形にしました（`連続紙 10x11インチ` と `連続紙 10x11インチ (ミシン目回避)`）。

### 長さ自体は制約になりません

「連続紙＝長いものが刷れない」と思われがちですが、この PPD は任意長のページを許可しています。

```
*MaxMediaHeight: "10000"     (= 10000pt ≒ 3.5m)
```

**1ページを 3.5m まで定義できる**ので、ミシン目をまたぐ長い表も「そういう寸法のページ」として
作れば刷れます。ページという枠に収まりさえすれば、長さは問題になりません。

### 本当に厄介なのは印字可能範囲

macOS は `ImageableArea` を信じてその範囲でラスタを作ります。**ここを間違えると
用紙外に印字しようとしてプリンタが物理的に停止します。** 最近のプリンタなら黙って
切り捨てるところを、この世代の機械はアラームで止まります。移植時にいちばん時間を
取られるのはここだと思います。

## プリンタをネットワークに載せる

本機は LAN ボードを内蔵していて、次のポートが開いています。

| ポート | 用途 |
|---|---|
| 9100 | RAW。**このドライバが使うのはここです** |
| 515 | LPD |
| 80 | Web UI（ページのエンコーディングは EUC-JP） |

IP アドレスがまだ決まっていない場合は、LAN ボードの設定から始めます。
うちの個体では **初期 IP が `11.22.33.44`**（NIC のスイッチを押すと設定情報が印刷されます）で、
設定用の PC を同じサブネット（`11.22.33.55` など）に寄せてからブラウザでアクセスし、
管理者設定画面でプリンタ名・IP・DHCP を変更しました。手順の詳細はこちらに書いてあります。

- [NEC MultiImpact 700XX : 古いインパクトプリンターのセットアップ](https://caciocavallo.jp/?p=1116)

設定済みなら、ブラウザで `http://<IP>/` を開けば状態を確認できます。うちの個体では
`/state.html` に用紙切れなどの状態が出て、`/opt.html` でプリンタ言語が `201PL` だと確認できました。
管理画面（`/frame.html`）はパスワードが要ります。

疎通確認はこれで足ります。

```bash
nc -z -v <IP> 9100
snmpget -v1 -c public <IP> 1.3.6.1.2.1.25.3.2.1.3.1   # 機種名が返る
```

### IP は固定する

**この LAN ボードは自分の名前を名乗りません。** Bonjour/mDNS より前の世代なので、
`.local` の名前は解決できず、`_pdl-datastream._tcp` をブラウズしても何も出てきません
（実機で確認済み）。SNMP の `sysName` は SNMP で読めるだけで、名前解決には使えません。

キューの宛先は `socket://<IP>:9100` なので、**IP が変わるとキューが壊れます。**
LAN ボード側で固定 IP にするか、DHCP を使うならルータで予約してください。

Mac 側で名前を付けること自体はできます。名前を解決するのはプリンタではなく Mac なので、
`/etc/hosts` に書けばホスト名で登録できます。

```
192.168.1.160   mi700
```

```bash
sudo mi700setup mi700 MultiImpact700XX
```

ただしこれは「読みやすい名前が付く」だけで、IP が変わったら結局書き換えになります。
LAN 全体で効かせたいならルータの DNS に静的エントリを置くのが本筋です。

なお**印刷ダイアログに出るのはキュー名**なので、見た目だけの話であれば
`mi700setup` の第2引数でキュー名を付けるほうが手軽です。

### 「プリンタを追加」の表示を整える（任意）

macOS の「プリンタを追加」は **SNMP の `sysLocation` を読んで「場所」欄に入れます**。
うちの個体は初期値が空白48文字で、場所欄が空白だらけになっていました。書き換えられます。

```bash
snmpset -v1 -c public <IP> 1.3.6.1.2.1.1.6.0 s "事務所"
```

`sysName` の方は macOS では使われません。手動で IP を入力して追加した場合、
プリンタ名にはアドレスがそのまま入ります。

## インストール

ビルド済みのパッケージを同梱しているので、そのまま入れられます。

```bash
git clone https://github.com/yukino1230/multiimpact-700xx-macos-driver.git
cd multiimpact-700xx-macos-driver
sudo installer -pkg dist/mi700-3.4.pkg -target /
sudo mi700setup <プリンタのIP>
```

自分でビルドする場合はこうです（`forms.conf` を編集したときもこちら）。

```bash
./driver/build-pkg.sh 3.4
sudo installer -pkg build/mi700-3.4.pkg -target /
```

### 署名と公証（配布する人向け）

`build-pkg.sh` は **Developer ID 証明書があれば自動で署名します**。無ければ未署名のまま
作られるだけで、ビルドは失敗しません。自分で使うぶんには署名は要りません。

公証まで通すには、`notarytool` の資格情報を一度キーチェーンに入れておきます。

```bash
xcrun notarytool store-credentials mi700 --apple-id <Apple ID> --team-id <Team ID>
MI700_NOTARY=mi700 ./driver/build-pkg.sh 3.4
```

フィルタを Hardened Runtime 付きで署名 → pkg を署名 → 公証 → `stapler staple` まで行います。
証明書を明示したい場合は `MI700_SIGN_APP` / `MI700_SIGN_PKG` で指定できます。

なお **`git clone` してビルドしたパッケージは、署名がなくても Gatekeeper に止められません。**
quarantine 属性が付くのはブラウザでダウンロードしたファイルだけだからです。

`mi700setup` が `socket://<IP>:9100` のキューを作ります。

### ターミナルを使わずに設定する

キューの登録は「設定」からでもできます。pkg はダブルクリックで入るので、
**この方法ならターミナルを一度も開かずに使い始められます。**

1. 「設定」→「プリンタとスキャナ」→「**プリンタ、スキャナ、またはファクスを追加…**」
2. 上部の **IP** タブを選ぶ
3. **アドレス**: プリンタの IP
4. **プロトコル**: **HP Jetdirect - ソケット**（LPD ではありません）
5. **キュー**: 空欄のまま
6. **名前**: 好きな名前。**ここが印刷ダイアログに表示されます**
7. **ドライバ**: `NEC MultiImpact 700XX` を選ぶ

7 は多くの場合**自動で選ばれます**。PPD が `/Library/Printers/PPDs/Contents/Resources/` に
入るので、macOS が SNMP で聞いた機種名（`hrDeviceDescr`）と PPD の `*ModelName` を
突き合わせてくれるためです。自動で選ばれなければ「ソフトウェアを選択…」から手で選びます。

「場所」欄には SNMP の `sysLocation` が入ります（[表示を整える](#プリンタを追加の表示を整える任意)）。

同じ IP に対して名前違いのキューをいくつでも作れるので、**用途ごとに分ける**こともできます。

ターミナルが要るのは、キューの既定値を変える `mi700default` と、状態を見る `mi700status` だけです。
どちらも印刷そのものには不要です。

パッケージは **Developer ID で署名し、Apple の公証も通してあります**。
ダウンロードしてダブルクリックするだけで入ります。確かめたい場合は:

```bash
spctl -a -vvv -t install mi700-3.4.pkg
# accepted / source=Notarized Developer ID と出れば正常です
```

削除は `sudo mi700setup --remove <キュー名>` です。

## 使い方

印刷ダイアログの「給紙」で給紙口を、「MultiImpact 700XX」の欄で排出方向と
印刷品質を選びます。コマンドラインからは次のように指定します。

```bash
lp -d <キュー名> -o PageSize=Cont10x11 -o InputSlot=reartractor -o OutputMode=std-bi file.pdf
```

| オプション | 値 |
|---|---|
| `InputSlot` | `feeder`（シートフィーダ）/ `guide`（シートガイド）/ `reartractor` / `fronttractor` |
| `OutputBin` | `front`（手前排紙）/ `rear`（スタッカ）※カット紙のみ |
| `OutputMode` | `std-bi` / `std-uni` / `draft-bi` / `draft-uni` / `none`（本体設定に従う） |
| `MI700Bottom` | ボトム領域の行数 `0` / `3` / `6` |

`-uni`（片方向印字）は遅くなりますが、双方向印字によるバンド境界のズレが出ません。

### よく使う設定を既定にする

macOS の「最後に使用した設定」はこのドライバでは復元されません（Apple 側の挙動で、
PPD からは制御できません）。代わりにキューの既定値を設定できます。

```bash
mi700default                                    # 現在の既定値と選べる値を表示
sudo mi700default 給紙=リアトラクタ 用紙=Cont10x45
```

#### ブラウザから設定する（macOS 26 まで）

> **macOS 27 では使えません。** CUPS の Web インターフェースが無効化され、
> `/printers/` も `/admin` も「ウェブインターフェイスが無効になっています」を返すだけになりました。
> **`cupsctl` の設定一覧から `WebInterface` の項目自体が消えている**ので、
> 有効に戻す手段もありません（実機で確認）。macOS 27 以降は `mi700default` を使ってください。

macOS 26 までは、CUPS の管理画面でも同じことができました。

```bash
sudo cupsctl WebInterface=yes
```

<http://localhost:631/printers/> でキューを選び、**Administration → Set Default Options**。
Mac の管理者アカウントで認証を求められます。給紙口・用紙サイズ・排出方向・印刷品質を
選んで保存すれば、`mi700default` と同じ結果になります。用が済んだら
`sudo cupsctl WebInterface=No` で閉じます。

### 用途ごとにキューを分ける

同じ IP に対して、名前違いのキューをいくつでも作れます。**給紙口と用紙を固定したキューを
用途ごとに用意しておくと、印刷ダイアログでプリンタを選ぶだけで設定が決まります。**
「最後に使用した設定」が復元されない以上、これがいちばん確実な方法です。

```bash
sudo mi700setup <IP> MI700_denpyo
sudo mi700default -p MI700_denpyo 給紙=リアトラクタ 用紙=Cont10x45

sudo mi700setup <IP> MI700_a4
sudo mi700default -p MI700_a4 給紙=シートフィーダ 用紙=A4
```

「設定」→「プリンタとスキャナ」から作っても構いません。その場合は作ったあとに
既定値を設定します。

> **キュー名に日本語を使うと内部名が壊れます。** 印刷ダイアログに出る表示名は日本語のまま
> ですが、CUPS 内部のキュー名は `NEC_MultiImpact_700XX_c_7c__c__c_5c__...` のように
> 変換されます。`lp -d` や `mi700default -p` で指定しにくくなるので、**キュー名は ASCII に
> しておくのが無難**です。内部名は `lpstat -p` で確認できます。
>
> 表示名だけ日本語にしたい場合は、ASCII のキュー名で作ってから説明を付け替えます。
>
> ```bash
> sudo lpadmin -p MI700_denpyo -D "MultiImpact 700XX 伝票"
> ```

### プリンタの状態を見る

```bash
mi700status <IP>
```

## 用紙を追加する

`forms.conf` は次のタブ区切りです。

```
名前	表示名	幅mm	高さmm	左mm	右mm	上mm	下mm
```

5〜8列目は**ページ座標での印字不可領域**です。ページの原点は用紙の左上ではなく
「印字ヘッドが到達できる最も左上の位置」なので、その分だけ右と下がはみ出します。
ここを用紙全面にすると**用紙外に印字しようとしてプリンタがエラーで停止します**（後述）。

編集したら PPD を作り直します。

```bash
sudo mi700setup <IP> <キュー名>     # forms.conf が新しければ PPD を再生成する
```

印字位置が怪しいときは、1枚刷って原点を実測できます。

```bash
mi700align Cont10x11 > a.ps      # 10mm 刻みの目盛りパターン
```

## 共有とリモート印刷

プリンタ自体がネットワーク上にあるので、**各 Mac に入れて直接使うのがいちばん簡単です**。
ここから先は、1台を経由させたい場合と、LAN の外から使いたい場合の話です。

### 1台の Mac を経由して共有する

**1台にだけドライバを入れて、他の Mac からはそれを経由して使う**構成にできます。
変換はサーバ側で行われるので、クライアントは PDF を送るだけです。

サーバにする Mac で:

```bash
sudo lpadmin -p <キュー名> -o printer-is-shared=true
sudo cupsctl --share-printers
```

そのうえで「設定」→「一般」→「共有」→「プリンタ共有」をオンにします。
他の Mac からは Bonjour で見えるので、「プリンタを追加」の一覧から選ぶだけです。

`mi700setup` が作るキューは `printer-is-shared=false` なので、共有したいときは
上のコマンドで明示的に有効にしてください。

`-D` で説明を付けておくと、それが Bonjour の名前になってクライアントに表示されます。

```bash
sudo lpadmin -p <キュー名> -D "MultiImpact 700XX (サーバ名)"
```

#### クライアントにもドライバを入れてください

共有プリンタは**クライアント側にドライバが無くても追加できます**が、その場合は
macOS がドライバレス（IPP Everywhere）として扱うため、**独自オプションが落ちます。**
実機で両方を確認した結果です。

| | クライアントにドライバ**あり** | **なし** |
|---|---|---|
| 用紙サイズ | 日本語名のまま全部 | 寸法は保たれるが名前が IPP キーワードになる（`iso_a4_210x297mm` など） |
| **ミシン目回避** | 使える | **消える**。IPP の用紙は寸法で識別されるので、同寸法の通常版に潰れます |
| 給紙口・排出方向 | 使える | 使える（IPP 標準の `media-source` / `output-bin` に対応づけてあるため） |
| **印刷品質・ボトム領域** | 使える | **消える** |

ドライバが入っていれば、macOS は**この PPD の選択肢だけを流用したクライアント用 PPD**を作り、
変換はサーバに任せます。独自オプションは IPP の属性としてそのままサーバまで届き、
フィルタに渡ります（ジョブ属性を `ipptool` で追って確認済み）。

ドライバを入れない運用にするなら、**サーバ側でキューの既定値を決めておく**か
（`mi700default`）、**用途ごとにキューを分けて共有する**と、選べない設定を補えます。

### LAN の外から印刷する（Tailscale など）

このプリンタの LAN ボードは 1998 年の世代で、当然ながら VPN を話しません。
外から使うには **LAN 内の Mac に橋渡しをさせます**。Tailscale で実際に検証した結果です
（MacBook をテザリングにして LAN から外し、Mac mini を LAN 側に置いた状態）。

方法は 2 つあり、**どちらも動きます**。

| | **A. サブネットルーター経由で直結** | **B. CUPS 共有経由** |
|---|---|---|
| 必要なもの | LAN 内のノードが `192.168.1.0/24` を広告 | サーバ側の CUPS 共有だけ |
| キューの宛先 | `socket://192.168.1.160:9100` | `ipp://<サーバ>.ts.net:631/printers/<キュー名>` |
| 変換をするのは | クライアント | サーバ |
| `mi700status` | **トンネル越しに使える** | クライアントからは届かない |
| tailnet に見えるもの | **LAN 全体** | **そのプリンタキューだけ** |

**セキュリティでは B が優れています。** サブネットルーターは LAN 全体を tailnet に晒しますが、
共有なら公開されるのはプリンタキュー 1 つです。**プリンタのためだけにサブネットルーターを
有効にする必要はありません。** 逆に、すでに常用しているなら A が手軽で、状態取得もできます。

#### 落とし穴は `dnssd://`

Bonjour で追加したキューの宛先は `dnssd://…_ipps._tcp.local.` になります。
**mDNS はサブネットを越えないので、LAN の外では名前が解決できず印刷できません。**
経路自体は生きているのに、名前解決だけが失敗する、という分かりにくい壊れ方をします。

宛先を VPN の FQDN に張り替えれば通ります。**キューを作り直す必要はありません。**

```bash
sudo lpadmin -p <キュー名> -v ipp://<サーバ>.ts.net:631/printers/<サーバ側のキュー名>
```

PPD はそのまま残るので、全オプションが使える状態を維持できます。LAN 内に戻ったときも、
Tailscale が直接経路を選ぶので速度は落ちません。

`ipp://` は平文に見えますが、**WireGuard が暗号化する**ので回線上を平文で流れることはありません。

#### サーバ側の前提

- **スリープさせない。** `pmset -g` で `sleep 0` を確認してください。寝ていると印刷できません
- **CUPS がリモートからの接続を受ける。** `cupsctl` で `_remote_any=1` になっているか確認します。
  ただしこれは**631 番に到達できる相手なら誰でも印刷できる**状態でもあります。
  据え置きの機械なら実害は小さいはずですが、信頼できないネットワークに繋ぐ場合は
  ファイアウォールで絞ってください

## PPD が使えなくなったときの移行先

Apple は PPD ベースの従来型ドライバを非推奨としています。そうなった場合の移行先は
**IPP Everywhere のプリンタアプリケーション**です。実際に試したうえでの記録を残しておきます。

### 変換部分はそのまま使えます

IPP Everywhere でプリンタが受け取るのは **PDF か PWG Raster** です。PWG Raster は
CUPS Raster v2 をベースにした規格で、**マジックもヘッダ構造も同じ**（`RaS2` / `2SaR`）。
このフィルタは **libcups に依存せずラスタを自前で解析している**ので、手を加えずに読めます。

```bash
cupsfilter -m image/pwg-raster -p <PPD> in.pdf > pwg.ras
rastertomi700 1 me job 1 "InputSlot=feeder" pwg.ras > out.prn   # そのまま通る
```

実際に通して、正常な 201PL が出ることを確認済みです。

### 土台は macOS に標準で入っています

`/usr/bin/ippeveprinter` が IPP Everywhere のプリンタとして Bonjour に名乗り、
ジョブごとに指定したコマンドを実行します。

```bash
ippeveprinter -D socket://<IP>:9100 -c $PWD/contrib/mi700ippcmd \
              -a <属性ファイル> -r _print,_universal "MultiImpact 700XX"
```

**`ippeveprinter` のオプションには、組み合わせられないものがあります。** どれも Usage を出して止まるだけで、
理由は表示されません。

| 組み合わせ | 代わりに |
|---|---|
| `-P`（PPD）と `-c`（変換コマンド） | 属性は `-a` のファイルに書く |
| `-a` と `-f`（受け付ける形式） | `document-format-supported` を属性ファイルに書く |
| `-a` と `-M` / `-m`（メーカー・機種名） | `printer-make-and-model` を属性ファイルに書く |

出発点として [`contrib/mi700ippcmd`](contrib/mi700ippcmd) を置いてあります。
ジョブの設定は **`IPP_<属性名>` の環境変数**で渡ってきます。ただし macOS から送ると、
給紙口は `IPP_MEDIA_SOURCE` ではなく **`IPP_MEDIA_COL` の中**（`{media-source=rear ...}`）に入っています。
**stderr の `STATE:` / `INFO:` / `ERROR:` / `DEBUG:` は CUPS フィルタとまったく同じ作法**なので、
用紙切れの通知もそのまま動きます。

### 書き直しが要るのは属性定義だけ

**`-P` で PPD を渡すことはできません。** `-c`（変換コマンド）と併用できず、
`-P` を指定すると変換コマンドが固定されてしまいます。用紙22種・給紙口・印刷品質の定義は、
`-a` の**属性ファイルとして書き直す**ことになります。

ただし `mkppd.py` が `forms.conf` から PPD を生成している構造はそのまま使えます。
**出力先を PPD から IPP 属性に変えるだけ**です。`media-size-supported` を書き忘れると、
用紙を指定したジョブが `Unsupported media-col collection value` で拒否されます。

### システム設定から追加するには URF が要ります

PWG Raster だけを広告したプリンタは、`lpadmin -m everywhere` なら追加できますが、
**システム設定（プリンタとスキャナ）のドライバ欄に AirPrint の選択肢が出てきません。**
**URF の広告と `-r _print,_universal` の両方**がそろうと追加できるようになり、
その場合 Mac は **URF で送ってきます**。つまり、ふつうに使えるようにするには
**このフィルタに URF の読み込みを足す必要があります**。

### 失われるもの

ドライバレス経路の制約をそのまま受けます（[共有の節](#クライアントにもドライバを入れてください)で実測したとおり）。

| | |
|---|---|
| **ミシン目回避** | **消えます。** IPP の用紙は寸法で識別されるので、同寸法の通常版に潰れます |
| **印刷品質** | `print-quality` は draft/normal/high の**3段階**。4種類は表せません |
| **ボトム領域** | 対応する標準属性がありません |
| 用紙名 | 日本語名ではなく `iso_a4_210x297mm` のような機械的な名前になります |
| 給紙口・排出方向 | **残ります**（IPP 標準の `media-source` / `output-bin` に対応づけてあるため） |

**今すぐ移行する理由はありません。** PPD 経路のほうが UI は優れており、macOS 27 の時点で
問題なく動いています。これは「そのときが来たら何をすればよいか」の記録です。

属性ファイルの生成・URF の読み込み・実機での検証結果は
[`ipp-everywhere` ブランチ](https://github.com/yukino1230/multiimpact-700xx-macos-driver/tree/ipp-everywhere)
で進めています。

### iPhone から印刷したい場合

AirPrint は **URF（Apple Raster）** を要求します。上に書いたとおり Mac のシステム設定から
追加する場合にも URF が要るので、**URF の読み込みは移行するなら避けられない作業**です。

### 「アプリを入れれば AirPrint のまま独自の設定が出せる」は macOS では成り立たない

AI やネットの記事で「プリント拡張機能アプリ（`UIPrintServiceExtension`）や `NSPrintPanelAccessorizing` を
使えば、AirPrint 接続のまま印刷ダイアログにメーカー独自の設定を出せ、その値は IPP の独自属性として
プリンタに届く」という説明を見かけます。**macOS 27 で確かめた限り、成り立ちません。**

- `UIPrintServiceExtension` は iOS / iPadOS 向けの**プリンタを探す**ための拡張機能で、画面は差し込めない
- `NSPrintPanelAccessorizing` は**自分のアプリの**印刷ダイアログ用で、他のアプリには効かない
- ドライバなしのキューに独自の設定（`-o mi700-bottom=6` など3通り）を付けて印刷すると、
  **CUPS の段階で捨てられ、プリンタ側には届かない**（実測）

これは Windows の **Print Support App** の仕組みと混同された説明のようです。
ミシン目回避・ボトム領域のような独自の機能は、PPD の経路で使ってください。

## 付属コマンド

いずれもパッケージに含まれ、`/usr/local/bin` に入ります。
普段の印刷は印刷ダイアログで済むので、ここにあるのは**検証と調整のための道具**です。

### mi700print — テキストをそのまま印刷する

UTF-8 のテキストを 201PL に変換します。CUPS を通さないので、ラスタ化を挟まず
プリンタ内蔵フォントで印字されます。速く、罫線のズレも出ません。

```bash
echo "見積書" | mi700print | lp -d <キュー名> -o raw
mi700print -w 100 < memo.txt | lp -d <キュー名> -o raw
```

| | |
|---|---|
| `-w 桁数` | 折り返し桁数（既定 80） |
| `-n` | 末尾の FF を送らない |

日本語は `ESC K` + JIS で送り、改行は CR+LF、ページ末尾に FF を付けます。
**変換できない文字は必ず2バイトの `〓` に落とします**。1バイトの `?` にすると
そこから先の漢字ストリームが全部ずれます。`～` `－` `∥` は CP932 と JIS X 0208 で
割り当てが違うので正規化しますが、**`￥` は JIS 216F に直接あるので正規化しません**。

### pdf2mi700 — CUPS を通さずに PDF/PS を変換する

ドライバを入れなくても使える旧経路です。ラスタ化に Ghostscript が要ります。

```bash
pdf2mi700 --source rear --quality std-uni doc.pdf > out.prn
lp -d <キュー名> -o raw out.prn
```

| | |
|---|---|
| `--source` | `feeder` / `guide` / `reartractor` / `fronttractor` |
| `--eject` | `front` / `rear`（カット紙のみ） |
| `--quality` | `std-bi` / `std-uni` / `draft-bi` / `draft-uni` / `none` |
| `--form-lines N` | 用紙長を行数で明示（既定はページ高さから算出） |
| `--bottom N` | ボトム領域の行数（規格の 25.4mm は 6行） |
| `--no-form-length` | 用紙長を送らず本体の設定に従う |
| `--paper NAME` | 登録済みプリセットの初期化列を使う |
| `--list` | プリセット一覧 |

### mi700decode — .prn を画像に戻す

**紙を使わずに出力を検証できます。** PBM を標準出力に吐くので、`sips` で PNG にできます。

```bash
mi700decode out.prn > out.pbm
sips -s format png out.pbm --out out.png
```

座標系が Windows ドライバと一致することを証明したのもこれです。実機で正しく印字できた
キャプチャをデコードし、こちらのドライバに通し直して、同じ座標にドットが来るか比べました。

### mi700align — 印字位置を実測する

用紙1枚で「ページの原点が用紙端から何mmか」を測るための、10mm 刻みの目盛りパターンです。
**トラクタを動かしたら測り直してください。**

**目盛りはページ座標**（ページ原点からの mm）で、基準線は**印字可能範囲の角**に引かれます。
ページ原点そのものには線を引きません。原点は印字可能範囲の外にあることが多く
（カット紙なら左1.6mm・上8.7mm）、そこに引いた線はラスタライズの時点で消えてしまうためです。

読み方は簡単です。**用紙の端から任意の目盛りまでを測り、その目盛りの数字を引く**と
ページ原点の位置が出ます。紙にも同じ説明と、印字可能範囲の角がページ座標で何mmかが刷られます。

```bash
mi700align                       # 登録済み用紙の一覧
mi700align Cont10x11 > a.ps      # 用紙名を指定
mi700align --size 210x297 > a.ps # 実寸を直接指定(mm)
```

PostScript を出すので、CUPS 経由で印刷するなら PDF に変換してから `lp` に渡します。

> **落とし穴:** Ghostscript に渡すファイル名を `align.ps` にしないでください。
> gs は自分のライブラリを先に探すので、**同名の gs 付属の `align.ps` を拾います**。

### mi700diff — キャプチャを命令単位で比較する

```bash
mi700diff a.prn b.prn
```

Windows 側で**設定を1つだけ変えて**採った2つを渡すと、その設定に対応する制御コードが
差分として出ます。給紙口や排紙方向のコードはこの方法で割り出しました。

### mi700preset — キャプチャをプリセットに登録する

```bash
mi700preset capture.prn rear     # 登録
mi700preset --list               # 一覧
```

登録すると `pdf2mi700 --paper <名前>` で初期化列を再利用できます。

> `.prn` は Windows 側でプリンタのポートを `FILE:` に変えて印刷すると採れます。
> **実際に印刷した内容がそのまま入るので、公開する前に `mi700decode` で中身を確認してください。**

## 実機で検証したこと

Windows ドライバが出力したデータを `FILE:` ポートで吸い出し、それと突き合わせて確定させました。
**推測ではなく、出力を測って確認したもの**です。

さらに 201PL リファレンスと 700XX2/JX3 のユーザーズマニュアルを、**実装が出す制御コード1つずつと突き合わせて精査しました**（2026-09-16）。齟齬はありませんでした。
実測で突き止めた「LSB が上端」「`ESC T` は 1/120 インチ」も、そのまま文書に記載がありました。

- **解像度は縦横とも 160dpi**（正方ピクセル）。全角24×24ドットの正方性から逆算
- `ESC J nnnn` + データ = 24ドットビットイメージ。1列3バイト、**バイト内は LSB が上端**
- `ESC F nnnn` = 横方向の絶対位置。1ドット = 1/160 インチ
- `ESC T nn` + LF = 縦方向の紙送り。**単位は 1/120 インチ**（1/180 ではない）、0〜99
- `ESC m 1/2/3` = 給紙口。**シートフィーダは `ESC a`（全排出後全吸入）が要る。**
  これを送らないと給紙後に「印刷可」を押すまで印刷が始まりません。
  シートガイドとの違いはこのコードを送るかどうかだけです
- **座標系は Windows ドライバと完全に一致します。** 実際に伝票へ正しく印字できた
  キャプチャを画像に戻し、このドライバに通し直すと、インク5176ドットが1つ残らず同座標に来ます
- **用紙外に印字しようとするとプリンタが停止します。** 本体表示は
  アラーム・高速印刷・用紙PE の点滅。A4 なら x=0 が用紙左端から 4.7mm 内側なので
  右限界は 205.3mm = 1293ドット。対処は PPD の `ImageableArea` を正しく書くことです
- **双方向印字のバンド境界のズレは本体の「罫線ぞろえ」で直ります。**
  1200dpi でスキャンして実測したところ、調整前 0.13mm が
  標準印字 0.011mm / ドラフト 0.060mm になりました（ドットピッチは 0.159mm）。
  ドット列印刷は**標準印字が HD、ドラフトが NHS** の調整に従います（マニュアルには記載なし）
- **ラスタは印字可能範囲ぶんしか無い。** CUPS ラスタの (0,0) はページ原点ではなく
  `ImageableArea` の左上です。ヘッダの `Margins` と `ImagingBoundingBox` を読んで
  その分ずらし戻さないと、**内容が左上にずれて印刷されます**（連続紙は余白0なので影響なし。
  カット紙で実測して発覚しました）。CUPS が持っているのは整数ポイントなので 0.2mm ほど丸められます
- **`FS 05v`（カット紙の用紙長）はどちらのマニュアルにも載っていません。** Windows の
  キャプチャ2つから逆算しました。単位は 1/120 インチで、**カット紙のときだけ +300（2.5インチ）**
  が付きます（連続紙の捕獲は `540` = 4.5インチちょうど、A4 のカット紙は `1703` = 11.69インチ + 2.5インチ）。
  これは**用紙の長さ**であってラスタの高さではありません。連続紙の `ESC v`（行数）も同じで、
  ミシン目回避の用紙（上下25.4mm）でラスタの高さを使うと2インチ短くなり、
  **改ページのたびに2インチずつずれていきます**（3.4 で修正）
- **SNMP は Host Resources だけ。** `hrPrinterDetectedErrorState` で用紙切れ・カバー開・
  紙詰まり・オフラインが取れます。Printer-MIB (1.3.6.1.2.1.43) は未実装なので、
  用紙残量・リボン残量・装着オプションは取得できません

## 推定にとどまること

- **A3 / B4 の対応**は 700XX2 の資料の表から読み取ったもので、700XX の実機では試していません
- **印字可能範囲**は NEC「用紙設計説明書」の**推奨印刷範囲**からの計算です。
  最大印刷範囲は「用紙ジャム、印刷ヘッドの故障等が発生する場合があります」と
  明記されているため採用していません
- **封筒・名刺**のサイズは定型用紙表からの引き写しで、給紙の可否は未確認です
- **原点オフセット**（カット紙 左4.7mm/上1.0mm、トラクタ 左32mm/上0mm）は実測値ですが、
  **トラクタの物理位置で変わります**。用紙を入れ替えたら `mi700align` で測り直してください
- 他の 201PL 系プリンタで動くかどうか

## 設計上の判断

- **ソフトウェアでの位置補正は入れていません。** 連続紙の位置合わせはトラクタを
  物理的に動かすのが本来の方法で、ソフトで補正すると責任が2箇所に分散し、
  設定が古くなっても**エラーにならず静かにズレます**
- **ページサイズは用紙の実寸**で定義しています。Windows のフォーム定義と同じにすることで、
  座標が完全に一致する利点を優先しました
- **ミシン目回避（上下25.4mm）は用紙サイズとして持たせています。** 本来は給紙口の属性ですが、
  PPD の `ImageableArea` は用紙サイズ単位でしか指定できないためです

## 他機種に移植する

201PL 系のプリンタなら移植できる見込みがあります。実際に効いてくる箇所と、
**紙を無駄にしない進め方**を書いておきます。

### 1. プリンタ言語を確かめる

```bash
snmpget -v1 -c public <IP> 1.3.6.1.2.1.25.3.2.1.3.1   # 機種名
```

LAN ボードの Web UI にも出ることがあります（うちの個体は `/opt.html` に `201PL` と表示されました）。
本体の設定状態印刷でも確認できます。ESC/P や NPDL なら別物なので、このドライバは使えません。

### 2. Windows のキャプチャを採る

**これが一番の情報源です。** プリンタのポートを `FILE:` に変えて印刷すると `.prn` が採れます。

**設定を1つだけ変えて2つ採り**、`mi700diff` にかけてください。その設定に対応する制御コードが
差分として出ます。給紙口・排出方向・印刷品質のコードは、すべてこの方法で割り出しました。

### 3. 紙を使わずに検証する

`mi700decode` でキャプチャを画像に戻し、**その画像を自分のドライバに通し直して**、
同じ座標に同じドットが来るかを比べます。座標系が一致していることは、これで紙1枚使わずに
証明できます。実機に出すのはその後で十分です。

### 4. 変える場所

| ファイル | 何を |
|---|---|
| `driver/mkppd.py` | `*Resolution`（dpi）、`*ModelName` / `*Product`、`InputSlot` の選択肢 |
| `driver/rastertomi700.c` | `BAND`（ピン数）、`TDPI`（`ESC T` の単位）、初期化列、給紙口・排出のコード |
| `forms.conf` | 用紙寸法と**印字可能範囲** |
| `driver/mi700setup` | 既定のキュー名 |

`*ModelName` と `*Product` は**ドライバの自動選択に使われます**。SNMP の `hrDeviceDescr` が
返す文字列と揃えておくと、macOS の「プリンタを追加」で IP を入れるだけでドライバが当たります。

### ハマりやすいところ

こちらが実際に外した順です。

- **解像度。** 横は `ESC F` の1ドット、縦は `ESC J` のバンド内1ドットです。700XX は
  縦横とも 160dpi でしたが、24ピン機は 180dpi のこともあります。全角文字が正方形になるか、
  既知の寸法の矩形を刷って実測するかで確かめます。
  **このドライバは正方ピクセルを前提にしています**（横は CUPS ラスタの1画素＝1ドット）。
  縦横で解像度が違う機種はフィルタの修正が要ります
- **バンド内のビット順。** 700XX は LSB が上端でした。逆にすると帯ごとに上下が反転します。
  `mi700decode` のビット順を4通り試して、読める向きを選ぶのが早道です
- **`ESC T` の単位。** 1/120 インチでした。1/180 と誤ると縦が 1.5 倍に伸びます
- **印字可能範囲。** ここを用紙全面にすると**プリンタがエラーで停止します**。
  メーカーの用紙設計説明書にある**推奨印刷範囲**から計算してください。最大印刷範囲には
  用紙ジャムやヘッド故障の注意書きが付いています
- **9ピン機。** `ESC J` は24ドット前提なので、8ドットの機種はビットイメージの
  組み立てから作り直しになります

## 構成

```
driver/rastertomi700.c   CUPS ラスタ -> 201PL のフィルタ（C、依存なし）
driver/mkppd.py          forms.conf から Shift-JIS の PPD を生成する
driver/build-pkg.sh      配布パッケージを作る
driver/mi700setup        キューを登録する
driver/mi700default      キューの既定値を設定する
driver/mi700status       SNMP でプリンタの状態を見る
forms.conf               用紙定義
tools/mi700print         UTF-8 テキストを ESC K + JIS で印刷する
tools/pdf2mi700          PDF/PS を Ghostscript 経由で変換する（CUPS を通さない旧経路）
tools/mi700decode        .prn を PBM に戻す（紙を使わずに検証できる）
tools/mi700align         印字位置の確認パターンを作る
tools/mi700diff          キャプチャ同士を比較する
tools/mi700preset        キャプチャをプリセットとして登録する
```

`tools/` の使い方は[付属コマンド](#付属コマンド)にあります。

PPD は `*LanguageEncoding: JIS83-RKSJ`、つまり **Shift-JIS** で出力します。
UTF-8 にすると印刷ダイアログの表示が文字化けします。
